### 1. Reference type vs. Value type
| Value Types | Reference Types |
| :--- | :--- |
| Directly Contain their data | Store references to their data |
| Each has own copy of data | Two reference variables can reference the same object |
| Operation on one DOES NOT affect the other | Operations on one can affect the other |
``` c#
    // Value Type, even though valueA is assigned to valueB, changes to valueA
    // do not change valueB
    int valueA = 5;
    int valueB = valueA;
    valueA = valueA + 1;
    Console.WriteLine($"A: {valueA}, B: {valueB}"); // Output: A: 6, B: 5

    // Reference type: when refA is assigned to refB they point to the same
    // Person object, so changes made through refA will change refB
    class Person { public string Name; }

    Person refA = new Person { Name = "Harry" };
    Person refB = refA;
    refA.Name = "Alice";
    Console.WriteLine($"refA.Name: {refA.Name}"); // Output: refA.Name: Alice
    Console.WriteLine($"refB.Name: {refB.Name}"); // Output: refB.Name: Alice

```

### 2. Boxing vs. Unboxing
Boxing and unboxing are conversion operations on variable types:
* Boxing: Converting a Value type into a Reference type
* Unboxing: Extracting the value type from a Boxed Reference Type
